配套：[方案-自由镇.md](方案-自由镇.md) Task 1、Task 4（257821 叠层）。对照 8.3.7.35662。地图 **1754**。

## 1. 必须删掉的脚本硬乘

文件：`BFA-HavenCore/src/server/scripts/KulTiras/FreeHold/instance_freehold.cpp`，函数 `instance_free_hold::OnCreatureCreate`。

现行（两条独立 `if`，不是 `else if`）：

- `instance->IsHeroic()` → `creature->SetBaseHealth(creature->GetMaxHealth() * 2.f);`
- `instance->IsMythic()` → `creature->SetBaseHealth(creature->GetMaxHealth() * 1.33f);`

`SetBaseHealth` 会改当前最大生命（`Creature.cpp` 约 1799–1804 行），第二次乘法吃的是已经 ×2 过的值。

难度 23 的 `Difficulty.db2` Flags = **133 = 0x85**，含 `DIFFICULTY_FLAG_HEROIC = 0x01`。因此 `Map::IsHeroic()` 在史诗五人上为真，再叠 `IsMythic()` → 史诗实际 **×2 × 1.33 ≈ ×2.66**。英雄 2 只 ×2。普通 1 不硬乘。

**本 Task 把这两条 `if` 整段删除。** GUID 的 `switch` 保留。

## 2. 三套数字都不是可任选的 8.3 DBC

禁止把其中任何一套写进 `SetBaseHealth` 或当成「普通:英雄」绝对比。

| 来源 | 英雄 | 非钥石史诗 | 身份 |
|------|------|------------|------|
| 暴雪 8.3 第 4 赛季说明 | 血伤 *increased by* 25% | *increased by* 45% | 补丁文案，相对当时地下城再上调，并下调钥石层数；不是 Difficulty.db2 |
| SQL `instance_difficulty_multiplier` | 1.29 / 1.29 | 1.612 / 1.612 | Trinity 自定义表。地图 1754 无普通行。`bfa_world.sql` 约 5087251–5087252 |
| Haven 脚本 | ×2 | ×1.33（再叠英雄旗成 ×2.66） | 私服硬乘，必须删 |

35662 `Difficulty.db2` **没有**血伤倍率字段。

`MapDifficulty.db2` 地图 1754：

| 行 | 难度 | ItemContext | ContentTuningID |
|----|------|-------------|-----------------|
| 3794 | 1 普通 | **17** | 500 |
| 3985 | 2 英雄 | 0（回落 Difficulty 上下文 2） | 501 |
| 3986 | 23 史诗 | 0（回落 23） | 502 |
| 4054 | 8 钥石 | （本阶段不做） | 502 |

ContentTuning 500/501/502 只有等级范围。浮点在 ExpectedStatMod。克拉格 `creature_template_scaling` 是 DifficultyID=0、**ContentTuningID=0**（`bfa_world.sql` 约 4316063）。Haven 现役血量主路径是模板 `HealthModifier` + 上述脚本硬乘，不是 500/501/502。本阶段**不**把 ExpectedStatMod 接进自由镇，只删错误硬乘。

删完后三难度基础生命都等于模板 `HealthModifier`（克拉格 **35**、三船长 **22**、托萨克 **36**、哈兰 **50**；`HealthScalingExpansion=7`）。

## 3. `instance_difficulty_multiplier` 实际乘什么

| 通道 | 自由镇是否走 | 乘的伤害类型 |
|------|----------------|--------------|
| 血量（`InstanceScript::OnCreatureCreate`） | **否**。只给奥迪尔 / 风暴熔炉 / 达萨罗之战 / 永恒王宫 / 尼奥罗萨 | — |

本阶段：

- 不 `UPDATE` dump 里 1754 的 1.29 / 1.612 行（不改 Databases）。
- 不把该表当五人全技能伤害倍率去「补」法术。
- 不把 1754 加进团本血量名单。
- 验收时登记：英雄/史诗白字是否仍约 ×1.29 / ×1.612；法术直伤应与普通同模板系数（相对白字表）。

## 4. 两套 `IsHeroic`（血量已删；技能开关在 F3）

| API | 史诗 23 | 英雄 2 | 用途 |
|-----|---------|--------|------|
| `Map::IsHeroic()` | 真（Flags 0x01） | 真 | 曾驱动血量 ×2，Task 1 删掉后不再用于自由镇血量 |
| `Map::IsMythic()` | 真（spawnMode 23 或 8 或神话团本） | 假 | 曾驱动 ×1.33 |
| `ScriptedAI::IsHeroic()` | **假**（只认 `DIFFICULTY_HEROIC==2`） | 真 | 俯冲/扔鱼饵现状；Task 5/6 改成 `IsFreeholdHeroicPlus`（2\|23） |
| `ScriptedAI::IsMythic()` | 真（转调 `Map::IsMythic()`） | 假 | **不能单独**当英雄+（会漏难度 2） |

`IsFreeholdHeroicPlus` 写在 `freehold.h`（Task 2 一并加）：

```cpp
inline bool IsFreeholdHeroicPlus(Map const* map)
{
    if (!map)
        return false;
    Difficulty const d = map->GetDifficultyID();
    return d == DIFFICULTY_HEROIC || d == DIFFICULTY_MYTHIC; // 2 or 23, not 8
}
```

禁止 `ScriptedAI::IsHeroic()` 冒充英雄+。钥石 8 本阶段不测；该宏故意不含 8。

## 5. 同一旗帜之下 257821 与难度生命叠层

35662 `SpellEffect` SpellID=257821，DifficultyID 全 0：

| 效果行 | 光环类型 | 基点 | 含义 |
|--------|----------|------|------|
| 481333 | 79 `SPELL_AURA_MOD_DAMAGE_PERCENT_DONE` | **100** | 伤害 +100% |
| 482632 | 133 `SPELL_AURA_MOD_INCREASE_HEALTH_PERCENT` | **100** | 生命 +100% |

Wowhead 现页伤害 +25% 是零售，禁止采用。

Haven：三人全敌对时每个船长 `CastSpell(me, 257821, true)`（`boss_council_o_captains.cpp` 约 599–601 行）。光环 133 走 `HandleStatModifier(UNIT_MOD_HEALTH, TOTAL_PCT, ...)`，与 `SetBaseHealth` 的 BASE_VALUE 是两层。Task 1 删硬乘之后：基础生命 = 模板；全敌对再 ×2（光环）。不要改 257821 的 SpellScript 去「避免叠层」。

三难度都会吃这条（SpellEffect 难度列全 0），前提是三人全敌对并成功上光环。入伙后必须 `RemoveAura(257821)`（Task 4）。
