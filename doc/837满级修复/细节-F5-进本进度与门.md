## 2. 必须改的进度接线

`SetBossNumber(DataMaxEncounters)` 已有（4 场：0 克拉格、1 议会、2 环赌、3 哈兰）。**没有** `SetHeaders`。地渊孢林先例：`the_underrot.h` `#define DataHeader "TU"`，构造里 `SetHeaders(DataHeader)`。自由镇加 `#define DataHeader "FH"`，在 `Initialize` 里调用。空头也能落盘 4 个 BossState（R2 未决 22 已闭合）；Headers 是最低集合格式前缀，不是存档开关。

现行 bug：`OnPlayerEnter` / `OnUnitDeath` 用 `GetData(DataCounciloCaptains)`。`ZoneScript::GetData` 读 `m_datas32`，本脚本从未 `SetData` 该 key，**恒为 0**。王脚本走 `SetBossState`。结果：议会打完仍当「没打完」。

改法：

- 读议会是否结束：一律 `GetBossState(DataCounciloCaptains)` 与 `DONE` 比较。
- `DataFriendlyCaptain` / `DataCrewEventDone` 用 `SetData`/`GetData`（这两个不是 bossId，放在 `DataMaxEncounters` **之后**，不要送进 `SetBossNumber`）。
- **删除** `countRaoul` 整条（`Initialize` 清零、`OnUnitDeath` 数 129547、成员变量）。

### 入伙进度：内存-only，不是落盘

`SetData` **不会**写入角色库 `instance` 存档。基类 `InstanceScript::GetSaveData`（约 596–604 行）只调用 `WriteSaveDataHeaders` + `WriteSaveDataBossStates` + `WriteSaveDataMore`；后者默认空。`SetBossState` 在状态变化时调用 `SaveToDB()`（约 510 行）；`SetData` 没有这条路径。

本阶段**明确**：

- 四王 BossState：走基类存档（补 `SetHeaders("FH")` 只改前缀格式）。
- 入伙（`DataFriendlyCaptain` / `DataCrewEventDone`）：**只存在当前 InstanceScript 对象的内存里**。同一副本会话内掉线，`OnPlayerEnter` 可以按 `GetData` 再 `DoAction` 恢复阵营。全员离开导致实例卸载、世界服务器重启、或过期后再进：入伙丢失，船长回到敌对，须重做当周事件。
- **不要** override `WriteSaveDataMore` / `ReadSaveDataMore` 把入伙写进存档（本阶段不做这套，避免假装已经落盘）。
- 方案正文禁止再写「友好进度落盘」。验收清单写「内存-only，重进丢失，进游戏验收」。

掉线拉回：不要传送到已通关王身边。`OnPlayerEnter` 只恢复入伙阵营（Task 3），且仅当实例对象仍在。克拉格/议会自写全灭 `EnterEvadeMode` 保持。
