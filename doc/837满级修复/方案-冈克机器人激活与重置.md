### 存档与数据号

`DataHeader` 已是 `"OM"`。core 先写两个头字符和 8 个 boss 状态，再调用 `WriteSaveDataMore`。More 里追加一个整数和一个空格，值只可能是 0..7。

在 `operation_mechagon.h` 的 `EncounterData` 之外增加：

```cpp
uint32 const DATA_SQUIRT_RELEASE_MASK = 8;
```

`EncounterCount` 仍是 8。这个号禁止传给 `SetBossState`。

`instance_operation_mechagon` 持有 `uint8 _releaseMask = 0`，并覆写 `GetData` / `SetData`。该号的读写只动这个成员。禁止把该号交给 `ZoneScript::SetData`：基类在值等于 3 时写 `last_data`，3 又是合法的部分 mask，`InstanceScript::SendNextData` 会把 `last_data` 当成场景步骤。其他数据号仍转给基类。

boss 和 `npc_mechagon_squirt_bot` 用 `instance->GetData(DATA_SQUIRT_RELEASE_MASK)` 读。缺省 0 与「三位都未记录」是同一种结果。

core 自己会把读到的 `IN_PROGRESS` / `FAIL` / `SPECIAL` 收成 `NOT_STARTED`，`DONE` 保留。加载时 `SetBossState` 碰到初值 `TO_BE_DECIDED` 会写入状态并返回 false，且不存盘。false 不是「没载入」。禁止为此重写 `SetBossState`。`ReadSaveDataMore` 在这 8 次调用之后执行，不要因为 false 跳过。

读档规则由头文件里的两个生产纯函数实现，实例只负责喂字符串和决定要不要查刷新时间：

1. `ClassifySquirtMaskToken(剩余字符串)` 返回 Absent、Accepted(0..7) 或 Rejected。先跳过前导空白。没有任何 token 才是 Absent。token 必须整段恰好是 `0`、`1`、`2`、`3`、`4`、`5`、`6`、`7` 之一，后面只许空白。`7junk`、`7 junk`、`-1`、`+7`、`00`、`07`、`8`、`9`、`15`、超过这些单字符的数字串，都是 Rejected。禁止 `operator>>` 进整数后再看成功与否，因为 `7junk` 会先读出 7。禁止 `& 7`、`% 8` 和其他把非法值折回 0..7 的运算。
2. 只有 Absent 才查刷新时间。对三只畸体 spawn 调用 `Map::GetCreatureRespawnTime`。`MaskFromRespawnTimes(t0,t1,t2)` 在对应时间非 0 时或上位 0、1、2，时间为 0 不置位。不读机器人的刷新时间，不把 store 里没有对象当成死，不 `Respawn`。查完若 mask 非 0，调用一次现有 `InstanceScript::SaveToDB()`，让下次加载变成 Accepted，避免刷新记录后来消失把位丢掉。mask 仍是 0 则不存。
3. Accepted 就采用该值，不查、不加刷新时间。
4. Rejected 则 mask=0，不查刷新时间，也不要 `SaveToDB` 把坏 token 洗成合法的 0。
5. 新实例 `CreateInstanceData(false)` 不调用 `Load`，本函数不跑，mask 保持构造时的 0。

`WriteSaveDataMore` 写出当前 0..7 和一个空格。脱战、`Reset`、DONE、第二次死亡都不把成员写成 0。显式读到 token `0` 时写成 0 是在采用存档，不是清档。

`OnUnitDeath` 里不要读 `m_respawnTime` 或 `GetCreatureRespawnTime`。该回调发生在 `Creature::setDeathState` 写入刷新时间之前。

`DamageTaken(Unit*, uint32& damage)`：在 `boss_gunker` 覆写。只把这次伤害引用改成 0 或保持原值。不改 `src/server/game/`，不靠 300859，不摘 300859。覆写必须调用 `squirt_lifecycle.h` 里的同一个 `bool GunkerAllowsDamage(bool hasInstance, SquirtBossState bossState, std::uint32_t releaseMask)`：返回 false 则 `damage = 0`，返回 true 则保留传入的 `damage`。`hasInstance` 表示这次有没有 instance。`bossState` 用该头已有的 `SquirtBossState`。`releaseMask` 用 `std::uint32_t`，以免非法值被截成 7；未开战时 `>= 8` 也不放行。该头不包含游戏头。本方案不写该函数的实现。`EnterCombat` 的 guard 和 DONE 时序仍按各自原文，不取消。下面三条是唯一判定，顺序固定：
