# A5 虚空仪式 — 正确做法与思路

对照：8.3.7.35662（含热修，见 [设计-腐蚀-Blizzlike.md](设计-腐蚀-Blizzlike.md)）。  
家：`BFA-HavenCore/src/server/scripts/Spells/spell_corruption.cpp`。  
第 1 层打桩：`.labritual` / `.aura 316814`。真装 318286 / ItemEffect **未做**。

本文只记**现在认定正确的做法和为什么这样选**。不记试错。

---

## 这份文档对齐的需求

1. 第 1 层能稳定复现：技能/法术（含治疗，不含白字平砍）有几率给自己上 **The End Is Coming（316823）**；之后约 20 秒内每秒加一层全次级 rating，最多 20 层。
2. 和好效果 / 坏效果两套管对齐：不进 `UpdateCorruption()`，不改 opcode / 核心施法。
3. 抄 A1–A4 的家、数据源、脚本层、验收；附近人数用范围检查，不要 `if (corruption`）。
4. 测试可以靠 HavenLab，战斗脚本不能依赖插件才能工作。

## 从 A1–A4 收来的经验（写之前先钉死）

| 教训 | 仪式怎么用 |
|------|------------|
| 数据能表达的不写死 C++ | 时长 20s、层上限 20、RPPM、ProcFlags、段 Dummy rating 读 `SpellInfo` |
| 伤害只走 `SetHitDamage` / `CalcAmount` | 这条没有伤害。rating 走 `SPELL_AURA_MOD_RATING` 的 `DoEffectCalcAmount` |
| `PreventDefault` + 唯一入口 | 开 buff 只走 `CastVoidRitual` |
| ID 只信 35662 | SimC 只理解链；附近倍率 5/6 是模型，不是 DBC |
| 不要用 `spell_proc` 改白字 | 316814 的 ProcFlags **已经有**黄字/治疗/敌对法术/周期/陷阱，**没有**白字。不要写 `spell_proc` |
| 已有 buff 不刷新 | SimC `buff_refresh_behavior::DISABLED`。已有 316823 时这次 proc 丢掉，不重开 20 秒 |
| GM 才打聊天 | `RITUAL_PROC` / `RITUAL_TICK` 仅 `.gm on` |

## 官方行为（第 1 层要看见的）

1. **开仪式：** 黄字技能/法术/治疗成功打出 → 316814 按 RPPM 1 proc → 自己身上 316823，从 **1 层**开始。平砍不出。
2. **爬坡：** 之后每 1 秒 +1 层，最多 20。每层全次级 rating += 段 Dummy（一段 14）。20 秒到点整段消失，不残留。
3. **已有 buff：** 再 proc **不刷新**时长、不加额外层（SimC TODO，清单按不刷新做）。
4. **附近：** 8 码内 ≥2 名同样挂着 316814 的友方玩家时，用完整 RPPM 1；否则按 SimC 把这次 proc 再掷 5/6。第 1 层单人木桩走「无人」分支，这是预期。
5. **多件：** SimC 把多段 Dummy 加到同一个 316823 上。第 1 层只测一段；多件等真装。

## 正确实现

代码：`spell_corruption.cpp`（往里加）。  
SQL：`sql/updates/world/2026_08_27_04_world_corruption_void_ritual.sql`  
  - `spell_script_names`：316814、316823  
  - **不**写 `spell_proc`  
注册：已有 `AddSC_corruption_spell_scripts()`。

| 技能 | 脚本 | 做什么 |
|------|------|--------|
| 316814 | AuraScript `OnProc` | `PreventDefaultAction()`。`CastVoidRitual`：已有 316823 则返回；附近不足则 5/6 再掷；否则 `CastSpell(316823)` |
| 316823 | AuraScript `DoEffectCalcAmount` + 周期 | 主人有 316814 才填 `Dummy × 层数`。无 316814：保持 0。周期 `ModStackAmount(+1, …, resetPeriodic=false, refresh=false)`。默认 `refresh=true` 会每叠一层重置 20 秒，整段变成约 40 秒 |

施法处禁止裸数字，一律 `enum VoidRitualSpells`。

316823 EFFECT_0 的 MiscValue `1913521920` 已经是暴击三项 + 急速三项 + 精通 + 全能三项。脚本只填 amount，不要自己拆 rating。

### 不要做

- 不要给 316814 写 `spell_proc`（会覆盖官方掩码 / RPPM）。
- 不要把 5/6 或 8 码写成「官方 DBC」。
- 不要平行 C++ 计时器替代 316823 周期。
- 不要把仪式写进 `UpdateCorruption()`。
- 不要猜外壳 324xxx。
- 不要已有 316823 时刷新 20 秒。
- 不要用默认 `ModStackAmount(+1)` 叠层（会重置时长）。必须 `refresh=false`。

## 怎么验收（第 1 层）

`.gm on` + `.labritual`（卸星/暮光/回响/触须，给自己 316814）+ 木桩：

- 猛击等黄字一会儿：`RITUAL_PROC`，自己出现 316823「末日将至 / The End Is Coming」。
- 之后约 1 秒一条 `RITUAL_TICK`，层数 1→20，一段 rating 14、28、42…；20 秒后光环掉。
- 平砍不应单独开仪式（和星一样：白字不在 316814 掩码里）。
- 人物面板暴击/急速/精通/全能应随层上涨。
- `.labstars` 之后不应再叠新的 316823。

真装 bonus `6540/6541/6542` 未接。附近 2 人加 proc：第 1 层不挡通过，需要第二名挂 316814 的玩家再测。

P0 代码侧（2026-08-27）：`VoidRitualNearbyAllies` 已加 `IsInPhase`；5/6 保持模型近似并写入热修白名单。HavenLab ritual pack 报告含「多人矩阵」（`allies` / `increased` / `skipped` + 单人 8%–28% 提示）。**待进游戏验收**：单人第 1 层清单 + 方案双端矩阵。DBC 字面 `allies >= 2`（除自己外两人）先不动。
