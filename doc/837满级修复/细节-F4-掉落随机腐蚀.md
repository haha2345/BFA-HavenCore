# 功能 4 细节：掉落随机抽出一条腐蚀特效

对照 **8.3.7.35662**。设计正文：[2026-08-29-corruption-loot-ranks-design.md](../../docs/superpowers/specs/2026-08-29-corruption-loot-ranks-design.md)。

## 1. 要解决的现象

`Loot::AddItem` 在 `ItemContext != NONE` 时只调用 `GetDefaultItemBonusTree`。该函数收集装等增量、品质列表、艾泽里解锁，**不会**从加成组抽随机 `腐蚀 -` 特效。`ItemBonusListGroupEntry.db2` 客户端有文件（fileDataId `3025306`），本核 Meta 已写，结构体注释掉且未加载。随机后缀表 `item_random_bonus_list_template` 为空，且本来就不是 8.3 腐蚀系统。

## 2. 正式服规则（已交叉验证）

下表用途：把玩法规则收成实现约束，避免把「有几率」做成「必出」或把排除槽位漏掉。

| 规则 | 来源 | 实现含义 |
|------|------|----------|
| 赛季 4 新装不再战火 / 泰坦造物，改为有几率被腐蚀 | 暴雪，Wowhead 新闻 295813 | 未腐蚀是合法结果 |
| 除艾泽里护甲、饰品外，各来源装备有几率带一条好效果 | Icy Veins | 资格过滤 |
| 恰好一条好效果，段越高腐蚀越多 | Icy Veins | 禁止一条装备两条 `腐蚀 -` |
| 同效果多件叠数值、不叠时长 | Icy Veins | 掉落无需处理，战斗已按求和 |
| 写死武器不再随机 | Icy Veins 武器节 | 先走功能 2 |
| 幻象后期必腐蚀 | Icy Veins / 蓝帖 2020-03-17 | 本阶段不做幻象，团本保持有几率 |
| 大秘 / PvP 周箱有资格则必腐蚀 | 暴雪 2020-01-27 | 本阶段不做周箱专路；本核周箱发奖物品上下文为空 |
| 段位不随团本难度 / 装等升高 | Ask Mr. Robot；组 158 选择器全 0 | 禁止按难度改抽签 |

随机池 **全服共用**：大秘、PvP、世界任务可以抽到暮光毁灭等签名效果；渠道不另做特效目录。六条武器独有效果不进随机池。本阶段主路径是团本/地下城 **尸体掉落**（有几率）。周箱正式服必腐蚀，但本核 `ChallengeModeMgr` 发奖时物品上下文为空、不套默认树，本阶段不挂钩周箱。

## 3. 8.3.7 抽签怎样接到物品上（第二轮已锁定）

**禁止：** 给 `ItemBonusTreeNode` 增加 `ChildItemBonusListGroupID`。wowdev 布局 `5F0770E4`（含 8.3.7.35662）没有该字段；9.0.5 布局 `C2E0B160` 才有。本核哈希已是 `0x5F0770E4`。

**已否决 — 类型 15 当组编号：** Wago 将 `ITEM_BONUS_RANDOM_ENCHANTMENT` 标为客户端预览；看到的行 `Value` 全 0、父列表 3407；没有任何树节点指向它。`AddBonus` 不处理类型 15 对 8.3.7 是合理的，不要按它接线。

**已否决 — 用 `item_random_bonus_list_template` 当权重：** 旧随机附魔表，当前为空。本核 `GenerateItemRandomBonusListId` 可以当挂钩，把抽出的列表 ID 写进 `LootItem.randomBonusListId`（封包会并进 `BonusListIDs`），但表本身不是 35662 真相。

**锁定路径：**

1. `GetDefaultItemBonusTree` 只负责装等 / 品质 / 插槽，以及写死武器那棵 **单节点** 专用树。
2. 可随机件（胸甲 `174164`）的 `ItemXBonusTree` 只有装等树 2748 + 空/品质树 2767，**没有**物品→腐蚀组的边。
3. 非写死武器常见随机树 **2819**（多子树，`matchingNodes != 1` 被跳过）。不要为了随机腐蚀去放宽「恰好一个匹配节点」——那会打乱装等树。树 2879 在 Wago 上 **没有** `ItemXBonusTree` 挂接。
4. 目录在 `ItemBonusListGroupEntry` **组 158**（约 69 条，`SequenceValue` 全 −1，`ItemExtendedCostID` 为 0）。服务端在默认树之后 **另抽** 一条（被动再补纯腐蚀列表）。
5. 「是否腐蚀」的百分比不在 DB2。用 `Rate.CorruptionDrop`（默认 0.25，非 35662）。

任务 0 转储仍要核对 **本机 ClientData** 是否与 Wago 8.3.7.35662 一致：

- 可随机：尼奥罗萨板甲胸 `174164`、萨德哈掉落锤 `172186`。
- 写死：`172191`（树 2893 → 6567）。
- 组 158：列出全部 `ItemBonusListID`。
- 排除对照：任意艾泽里胸、任意 8.3 饰品。

## 4. 加成组表怎么用（8.3.7）

加载字段必须与 Meta `0xCA17B2FF` 一致，顺序与 wowdev 8.3 布局相同：

1. `ItemBonusListID`
2. `ItemLevelSelectorID`（0 表示不按装等过滤）
3. `SequenceValue`：组 158 **全是 −1**，不能当权重，也不能当「6474+6455」成对键
4. `ItemExtendedCostID`：组 158 为 0。非 0 的条目当商店价签，掉落路径跳过（本阶段不做玛乌尔）
5. `ItemBonusListGroupID`（关系键；8.3.7 没有父表 `ItemBonusListGroup.db2`）

不要加载 9.0 的 `PlayerConditionID` / `Flags`。

过滤后的池：组 158 减去独特武器列表 6567–6572、空列表 6516、未对上的 6487–6492 / 6496–6498。签名段 6537 起 **保留**（随机装可以出暮光 / 附肢 / 仪式各段）。均匀抽取；权重未知。

## 5. 一条「特效」可能是一条或两条列表

签名 / 武器式列表：抽中 6552 即无尽之星一段 + 20 腐蚀（同一条还带类型 24，本阶段忽略）。  
被动：6474 **只有类型 23**。抽中后必须再挂纯腐蚀列表。Wowhead：`bonus=6474` 无腐蚀，`6474:6455` 才有 +10。

被动配对按 **腐蚀点数**，不要写死单一 Cor 列表 ID：

| 点数 | 优先列表（现场更常见） | 备选（SimC / 商店档） |
|------|------------------------|------------------------|
| 10 | 6455 | — |
| 15 | 6462 | 6460 |
| 20 | 6470 | 6465 |
| 虹吸者 17 / 28 / 45 | **6612 / 6613 / 6614** | 禁止用 6455 套虹吸者 |

组 158 不能靠 `SequenceValue` 成对。实现里用「效果列表 → 点数 → 优先 Cor 列表」映射（见细节-F3）。

## 6. 调用点

主路径：`Loot::AddItem`（`src/server/game/Loot/Loot.cpp`）。地图已设 `_itemContext`（例如 `GetDifficultyLootItemContext()`）。

同一展开函数还应挂到其它「已经调用 `GetDefaultItemBonusTree`」的发装点，避免只修尸体掉落。检索 `GetDefaultItemBonusTree` 的调用点，逐个决定。已显式传入完整 `bonusListIDs` 且含腐蚀列表的调用方（`.additem`）不得再抽。

挑战模式 `ChallengeModeMgr.cpp` 若自己组加成，要对齐：可腐蚀奖励件走同一展开，写死武器走功能 2。

## 7. `.labgear`

板甲套装保持无随机腐蚀，用于确定性打桩。功能 4 的验收靠团本地图掉落或一次受控的「强制抽签」GM 命令（若要加，只能是调试命令，且须标明非正式服）。不把随机抽签塞进现有 `.labgear`。

## 8. 验收

- 可腐蚀胸甲、非写死武器：多次掉落，同时存在未腐蚀与恰好一条腐蚀。
- 腐蚀实例：人物面板有腐蚀点数，且有一条好效果光环；不会出现「只有点数没有效果」或「只有效果点数为 0」（被动漏挂配对列表）。
- 艾泽里、饰品：零随机腐蚀加成。
- `172191`：只有 6567（外加装等 / 品质），没有 6474 之类第二条特效。
- 编译 RelWithDebInfo `worldserver`。进游戏验；不能只靠编译通过声称功能 4 完成。
