## 最小生命周期模型

所有权留在 Rummy AI：一个 `brewStarted` 和至多一个 `EventLaunchBrew` 等待事件即可。不保存 `Spell*`、目标 `Unit*`、落点或异步任务句柄；不新增 core 对象、全局调度器、地图外管理器或捕获 `this` 的延迟回调。等待与正在正常读条是运行期的两个情形，成功效果不建状态。

启动仍来自现有船长 Start action。instance 只统一停止通知，不在每次 IN_PROGRESS 通知时重新启动，避免三位船长进战或加载状态造成重复链。Rummy 接收 Start 时要求：实例存在、实际议会状态 IN_PROGRESS、沿用现有 `IsFreeholdHeroicPlus` 入口资格、自己可用、`brewStarted=false`。先清空旧 events，再置运行标志并排唯一一次 8 秒首发；后续重复 Start 保持现有时轴，不重排首发、不添加第二事件。

现有 `IsFreeholdHeroicPlus` 明确只认难度 2/23，不含 8。本稿沿用此准入，不宣称难度 8 已启动，不顺手改全本难度规则；历史高钥石样本的节奏证据与当前本地启动资格分开记录。正式技能/难度覆盖留给后续方案核对。

本期临时保留现有候选收集与随机技能选择作为调用适配：50 码玩家/存活船长等现状**不是历史正确目标池**。不添加宠物、非船长池，不改半径，不借 observed recipient 推导 cast target。传入现有 target 不保证法术保留显式单位：基础 mask=0 时 `InitExplicitTargets` 可以移除它并按 caster 建目的地。这里不修 target enum、SpellMgr、位置重载或 DUMMY。

## 8 秒从 start 计时

SpellCastTimes14 为 Base3000/PerLevel0/Minimum3000，复用加载数据和正常 `CastSpell(target, brewId, false)`。禁止 AI 写死 3 秒计时器、覆盖 casttime、triggered 后伪造读条。运行时 `ModSpellCastTime`、速度及脚本等仍可改变读条，3000ms 是基础值。**8000ms 来自已审核 WCL 的 begin 节奏，不是 DBC 字段。**

首次有效 Start 为 t0，首发在约 t0+8s 开始；成功 prepare 的同步调用时刻就是本调度的 start 锚。在这次调用返回后，仍运行且实际 state 仍 IN_PROGRESS 才排唯一一次“从本次 start 起 8 秒”的下一事件。正常链近似：begin 8s、16s、24s；未受修正的 cast 约 11s、19s、27s。不是完成后再等 8 秒，也不是以 apply 为下一轮锚，更不是用约 5 秒 cast→apply 来认可现有 Repeat(5000)。

时间推进继续用 Rummy 自有 EventMap；活动期间 `events.Update(diff)` 在 CASTING 检查之前，所以读条的 3 秒包含在 8 秒周期内。每个 Update 最多消费一次 launch，不在 while 中补发过期次数。CASTING 时保留至多一个到期事件，待读条解除后只尝试一次；迟到后以这次真实 start 重锚，不追赶成一帧多投。tick 迟延、加速/减速及装载差异应在人测记录，不能承诺严格墙钟 8000ms。

空候选本轮不调用 CastSpell，以本轮尝试时刻为锚等待下一次 8 秒机会。prepare 返回 false 同样丢弃本轮、只排一份 8 秒重试机会；此 8 秒是沿用节奏的保守失败策略，不宣称历史空目标规则已证。prepare 成功后的中断/完成失败不补发、不提前重排；已有下一次 start 机会保持。任意停止先清运行标志和事件，所以调用返回后的排队必须再次检查标志与 state，防同步重入把停止后的链复活。所有失败不得零延迟重排、递归 CastSpell、同 tick 换目标重试或 busyloop。

不覆盖 `OnSpellFinished` 来维护本循环，也不在其内发下一酒、安排 apply、置成功状态或把 CASTING 当已清除。CastSpell 返回 true 只证明 prepare 被接受；生命周期允许下一次尝试不等于上一轮 HIT、Aura 或来源归属已正确。

## 同步取消与 encounter 边界

定义一个留在 Rummy AI 内的共同停止入口，供 `Reset()` 和 `ActionResetRummy` 调用。顺序固定：**先 `brewStarted=false`，再 `events.Reset()`，最后按三个发起 spell ID 分别调用 `InterruptNonMeleeSpells(true, brewId, true)`**；保持现有被动/不可选中及适当清威胁行为。限定 ID 不取消邻居技能；true 包含可取消的 delayed 状态。反复调用结果相同，没有 pending launch；取消引发同步 finish 也不能重新入队。Rummy 自己 Reset 必须取消正在读的酒，不能只清 EventMap。

`ActionResetRummy` 当前全文只见 enum 与 case，没有调用方；不应把现状说成已可取消。未来接线最小集合如下，只有局部脚本变动的架构意图，本稿不实施：

| 入口 | 同步处理及重复通知 |
|---|---|
| 船长 `Reset()` | 在本入口开始即以 GUID 发 Stop；原有 NOT_STARTED 通知继续走 instance。重复 Reset 均可 Stop，不能因状态未变就漏取消 |
| 船长 `EnterEvadeMode()` | **进入函数即 Stop，在现有防重复/`!reset` 早退之前**；若实际议会仍 IN_PROGRESS，同步请求 FAIL，再做原有回家流程。避免只等 JustReachedHome；FAIL 也使迟到的 Start 被拒绝 |
| 船长 `JustReachedHome()` | 入口先 Stop；沿用 `_JustReachedHome`、FAIL、Reset，幂等吸收多船长的重复通知，不让返回途中又起酒 |
| controller 写 DONE | 覆盖 `instance_free_hold::SetBossState`，调用基类并读回实际 state；确认议会已非 IN_PROGRESS 即在同调用栈 Stop。基类拒绝 DONE、实际仍 IN_PROGRESS 时不把请求冒充完成；不改 controller 判死规则 |
| 任意议会 NOT_STARTED/FAIL/DONE 通知 | 无论基类返回 true/false，依据调用后实际非 IN_PROGRESS 发送 Stop；覆盖“重复 state”和“加载赋值但返回 false”。其他 boss id 不通知 Rummy |
| 已 DONE 的 reset/迟到 state | instance 局部覆盖对议会 DONE 保持完成态，拒绝本生命周期的 IN_PROGRESS/FAIL/NOT_STARTED 回退，同时同步 Stop；不为三位船长 Reset 抹掉已装载/已完成的 DONE。不改通用 InstanceScript |
| 真正重进战 | FAIL/NOT_STARTED 后新的合法 IN_PROGRESS 与船长 Start 可启动一条新链，重新等待首发 8 秒；旧事件已清零。DONE 不允许重新启动 |

选择 instance 的局部 GUID + 现有 AI action，而非每帧扫邻近 Rummy 或新增核心对象。船长三个局部入口使用同文件的同步通知辅助逻辑；共享 action enum 放入现有 `freehold.h`，保留既有值。instance 状态统一停止承担 controllerDONE 和非船长状态入口；显式船长入口承担 evade 尚未回家及基类回调前的时间窗口，二者重复通知由 Stop 幂等消化。

Rummy `UpdateAI` 的运行/state 检查是兜底：非 IN_PROGRESS 或不可继续活动时调用 Stop 并退出；它不能作为唯一取消手段。`Unit::Update`（Unit.cpp:471）先更新 `m_Events`，`Creature::Update` 中 Unit 更新早于 AI 更新（Creature.cpp:692/706、792）；SpellEvent 可能先完成。故 Stop 必须在 encounter 终止的同步入口打断正在读条的 Spell，而不是等下一次 NPC UpdateAI。若 SpellEvent 已经在终止通知之前完成，不能追溯撤销其既有结果；保证的是终止入口之后不继续本轮读条、不产生新 launch，不声称清掉尚未研究的完整酒区域或 Aura。

## GUID、装载与析构

Rummy GUID 是 `instance_free_hold` 成员，Initialize 置 Empty，OnCreatureCreate 按现有 entry 登记，GetGuidData 增加 Rummy case。Creature.cpp 的创建流程先 `OnCreatureCreate`，后入对象 store，再 `AIM_Initialize`；**不能在登记时强行调用尚未初始化的 AI**。此处只登记；Rummy 构造/InitializeAI→Reset 保证初始 stopped，不因加载 IN_PROGRESS/DONE 自动启动。装载 DONE 时 state 门阻止 Start；基类加载分支 bool=false 不使 DONE 丢失。

OnCreatureRemove 在对象尚在世界的正常移除入口检查匹配 GUID，AI 存在则同步 Stop，然后仅清匹配 GUID，保留基类移除职责；避免旧对象移除清掉后来的登记值。通知解析失败视为对象已不可用，不缓存裸 Creature*/AI*，不跨地图保存 GUID，不安排“稍后再找它”的闭包。缺失 Rummy 不靠定时扫描自动起酒；重建对象默认 stopped，后续只有合法现有 Start 可启动。

地图析构不增加会遍历已释放 instance/Creature 的自定义析构回调。AI 的 EventMap 与 AI 一起销毁；普通移除由上述入口停止；基础 Unit 清理 `m_Events`，Unit.cpp:412–422 的析构含 `KillAllEvents(true)`，Spell.cpp 的 `SpellEvent::~SpellEvent/Abort` 与现有 Spell 所有权负责 core 事件释放。生命周期本身没有捕获 AI/instance/target 的新回调，故不引入 dangling callbacks；不调用通用 KillAllEvents 清邻居，不改 SpellEvent。船长现有 Reset 中的 3 秒 `AddTimedDelayedOperation([this])` 是既有周盟逻辑，本稿不为其全局安全背书，也不把新循环接到它上面。

本模型没有一个独立异步 apply 队列，也就没有需要发明 epoch/generation 的 apply 回调。后来若批准弹道/延迟机制，必须另审完成语义、地图对象生命周期和代际取消，不能把本稿的 start 队列直接充当效果队列。

## 决策结论

保留 Rummy/议会/instance 三个现有家；`triggered=false` 让引擎读 CastTimes14；8 秒从 start 计时，失败仅下一节奏机会重试；Start 去重，Stop 先关标志清事件再同步限定 ID 取消。instance 局部 GUID/state 通知与船长 Reset/evade/home 入口共同封住 SpellEvent 先于 UpdateAI 的窗口；读实际 state 处理重复通知和加载 bool=false，DONE 本地保持完成态。没有新异步回调或 apply 队列，生命周期不引入悬垂回调。完整效果、trap 和未决历史行为不越证据门；架构 R1/R2 待审。
